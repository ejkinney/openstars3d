# P2 OpenCode dialogue handoff — 2026-10-29

The optional server companion now sends one stateless generation request through the configured local OpenCode service. It discovers the service without starting or reconfiguring it, supplies the service's auth headers via `Service.headers`, and pins `opencode/mimo-v2.6-flash-free`. Before enabling generation it checks the project catalog for an active, enabled chat model with zero input and output price. It never reads or stores provider credentials. Normal `node server/local-server.cjs` remains deterministic/offline. `server/live-validation.cjs` is retired and cannot call DeepSeek.

To opt into the free companion after live validation is authorized: `node server/opencode-companion.cjs --enable-free-dialogue`. Startup performs discovery/catalog reads only. If the service or free model is missing, the companion reports deterministic fallback. Stop with Ctrl+C. The adapter permits four total generation attempts per process, including failures. Each prompt is at most 6000 UTF-8 bytes. Returned text is limited to 8192 bytes, must parse as a single-key JSON reaction, and passes the existing 12–240 character/40-word content screen. The API's one-shot `generate.text` route has no provider-side max-output-token option; the earlier 160-token bound cannot be carried over as a provider-side limit. The 10-second local timeout aborts the request where the service honors cancellation; a race may finish server-side after cancellation. No hard account quota or generation-quality guarantee is claimed.

Canonical advice, actions, resources, and outcome remain local and authoritative. Generated reaction text is optional and separately labelled. A timeout, unavailable service, malformed response, or request cap uses the preset offline fallback. The runtime already rejects late dialogue after restart.
